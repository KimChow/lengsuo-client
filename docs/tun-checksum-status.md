# TUN 传输层校验和实现与验收状态

范围仅限 `crates/lengsuo-tun` 的传输层校验和验证，不含任何平台 TUN 设备驱动、
路由安装或系统设置改动。参考基线为 RFC 1071（一补码和）、RFC 768（IPv4 UDP 校验
和可选）、RFC 8200（IPv6 UDP 校验和必需）与 RFC 9293（TCP 校验和覆盖伪首部）。

## 已实现

- `checksum::verify(packet) -> Result<PacketInfo, Error>`：先调用 `packet::inspect`
  取得已核对的头部元数据，再验证 TCP/UDP 校验和。只读，不改写报文。
- 校验和覆盖伪首部加整个传输段（头部、选项与应用数据，含校验和字段本身），
  折叠后的和必须为全 1，否则失败。
- IPv4 传输段自 IHL × 4 起始，伪首部地址取自偏移 12..20、协议取偏移 9、长度字段
  为 16 位；IPv6 传输段自固定 40 字节起始，地址取 8..40、长度为 32 位、下一头取
  偏移 6。协议号直接读取头部字段，与 `inspect` 已接受的字段一致。
- 末尾奇数字节按尾部补零计入；进位循环折叠回 16 位；累加使用 `u64`，达到溢出需
  要 2^48 个字，真实报文长度下不会溢出。
- 零校验和策略：IPv4 的 UDP 字段为 0 表示发送端未计算（RFC 768），本模块按未提供
  放行，并在使用中记录这一放行不等于该数据报未经损坏；IPv6 的 UDP 字段为 0 一律
  拒绝（RFC 8200）；TCP 在两个版本下都必须校验，字段为 0 也照常计入求和，不跳过。
- 错误种类：`Error::Packet(packet::Error)` 逐字保留头部解析失败（分片、扩展头、
  长度不一致、IPv4 头部校验和失败等），`Error::TransportChecksum` 表示传输层校验和
  不正确或 IPv6 UDP 收到零值。`packet.rs` 与其 `Error` 未改动，未新增依赖，
  crate 保持 `#![forbid(unsafe_code)]`。

## 已验证

15 项 checksum 测试实际通过（3 项模块内单元测试 + 12 项集成测试），另 15 项原有
`packet` 测试保持不变并通过：

- RFC 1071 固定向量 `00 01 f2 03 f4 f5 f6 f7`：折叠和 0xddf2、发送端校验和 0x220d，
  期望值取自 RFC 文本而非由本实现反推；把 0x220d 接回数据后接收端和为全 1。
- 奇数尾字节补零、逐段与连续缓冲等价、进位循环折叠。
- 自造正确的 IPv4/IPv6 TCP 与 UDP 报文（含 IHL 5/6/8/15、零载荷、偶数与奇数载荷）。
  测试侧用独立写法的一补码和生成校验和，不复用被测算法。
- 篡改源 IP（同时回填 IPv4 头部校验和以逼出传输层检查）、源端口、载荷末字节、
  IPv6 源/目的地址，均返回 `TransportChecksum`。
- IPv4 UDP 零校验和放行、IPv6 UDP 零校验和拒绝、TCP 校验和篡改为零拒绝；新增正例证明两个版本的 TCP 字段恰好计算为零时仍合法。
- 所有前缀截断一律失败、纯噪声输入不 panic；头部问题保持 `packet::Error` 原种类。

`cargo fmt --all -- --check`、`cargo clippy -p lengsuo-tun --all-targets -- -D warnings`、
`cargo test -p lengsuo-tun` 均通过。四个文件分别为 227/17/309 行加本文档，未超 400 行。

## 明确未实现与不声称

- 不验证 TCP 状态机、序列号、标志位语义或连接方向；不解析 IP 选项内容；不重组
  分片（分片与 IPv6 扩展头仍由 `packet::inspect` 直接拒绝）。
- 传输层校验和只覆盖伪首部与传输段：IPv6 固定头部的通信类、流标签和跳数限制不在
  覆盖范围内，也没有 IPv6 头部校验和可依赖，改动这些字节仍会通过验证。测试已显式
  记录这一范围，不得据此声称逐字节篡改检测。
- 本模块只做校验和验证，不做设备接入：Windows/Linux TUN 读写、用户态 TCP/IP 栈、
  环境分流、DNS、MTU、ICMP 错误路径、断线与休眠恢复、出口协议连接均未实现。
- 测试全部是本地固定字节与独立算法对照，不构成与真实网卡、内核协议栈或任何第三方
  实现的互通证据；未经实测不得描述为完整入站安全验证或协议兼容完成。

集成复核修正了“TCP 零字段一律非法”的注释，保留正确实现：TCP 字段为零时
仍须计算完整校验和，并不自动拒绝。新增独立构造的零值正例防止后续误改。
