# Agent 续开发与验收计划（2026-10-17）

## 失败原因与调整

四个会话都以 error_max_turns 退出，并非正常完成。原卡合并多个模块、探索、实现和验收，60轮不足。
日志同时出现不存在的路径/工具名、跨到无关任务的命令，说明任务偏离；不能只靠提高轮数解决。
原调度未在达到上限后继续处置，是本轮交付中断的另一原因。

调整：每卡一个可验证缺口；固定工作区及文件清单，启动前提供真实接口和失败用例；
新会话不恢复已经偏离的旧上下文。中途检查实际文件与测试结果，发现连续错误立即纠偏。
测试、完成报告和提交必须对应源码；测试0项不得收卡；先提交独立完成项，再集成跨模块链。

## 顺序

1. 提交能力核验报告，纠正文档过度声明。
2. 记忆路径防护、运行时脱敏及开关：各自红灯复现，修复后全crate验收。
3. 凭据调试输出清理、策略判定器、MCP stdio测试、shell回环测试分别独立卡。
4. 网关先完成鉴权/RPC，再补WS、隔离、并发与关闭。
5. 沿既有文档把提示词/记忆/任务/Skills/MCP接入宿主；未批准的新接口先写提案，不伪造已实现。
6. GPUI先落可编译入口与一个视图，再补三视图及实际网关联调；平台限制明确记录。

真实LLM、终端sidecar、定时自动化、fjall、浏览器工具仍按既有冻结范围处理，不擅自扩展。
本计划不修改AGENTS规则；700/400、TDD、独立target、默认拒绝、脱敏及测试后合流继续执行。
