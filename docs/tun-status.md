# TUN 实现与验收状态

当前只实现安全 Rust IP 报文元数据解析，不创建平台 TUN 设备，不修改系统路由。

- IPv4 核对 IHL、精确总长度与头部校验和，拒绝 MF 和非零分片偏移。
- IPv6 核对固定头部与精确载荷长度；当前显式拒绝扩展头和分片。
- 仅接受直接 TCP/UDP，核对 TCP 数据偏移和 UDP 精确长度。
- 全程检查切片和偏移；元数据包含地址、端口及载荷偏移，不含环境身份或 PID。
- 不解析 IP 选项语义，不验证 TCP/UDP 校验和，不重组分片，不能作为完整入站验证。

Claude Code 的隔离会话产出解析器与十五项测试，达到轮次上限后由集成负责人接管。
复核发现测试的两个 Clippy 警告和单文件 457 行软目标超限；修正后将构造器按职责
拆到 tests/support，保留原测试语义，未删注释或压行规避。

十五项测试已实际通过：IPv4 TCP/UDP、IPv4 options、IPv6 TCP/UDP、全部截断、
非法版本与长度、IPv4 坏校验和、IPv4 分片、IPv6 扩展头、TCP 偏移、UDP 长度，
以及确定性垃圾输入下不崩溃。严格 Clippy 无警告通过。

尚未实现 Windows TUN 设备接入、用户态 TCP/IP 栈、可信浏览器环境入口、DNS、
MTU 与 ICMP 错误路径、出口协议连接、路由安装撤销、断线与休眠恢复。
不能凭本解析器从共享 TUN 包推断可信环境，也不能用十五项测试声称浏览器 TUN
验收完成。最终仍须真实浏览器 A/B/C 同域名同 IP 各走指定设备、无泄漏、
撤销隔离、非受管流量不变，并在 Windows 实机上逐项记录证据。
