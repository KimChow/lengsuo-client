# 跨端测试向量

本目录存放**跨端（PC ↔ 移动端）测试向量**：同一份输入，在不同实现里必须得到
**同一串字节**。移动端与 PC 各自拿这份文件做**跨实现对拍**。

向量是**跨端契约**，不是随手写的测试夹具。

## 三个文件

| 文件 | 内容 |
|---|---|
| `session-vectors.json` | L2 会话：握手报文、派生密钥、收发帧的字节级向量 |
| `error-vectors.json` | 错误路径：确定性输入 → **稳定错误标签**的映射 |
| `frame-vectors.json` | L3 帧编解码：明文 → 帧字节（含定长头、CRC、序号） |

## 怎么读

每份 JSON 顶层都有三个字段：

- `format`：格式标识（如 `lengsuo-link-session-vectors`）。**先比对它**，
  不认识就应当拒绝解析，而不是「尽力而为」。
- `version`：版本号。**与本端实现支持的不一致时必须拒绝**，不得按旧版语义猜。
- `spec`：该向量对应的规范文档路径。

其余字段按各文件的结构取用（会话向量是 `links[]`，每条含 `rounds[]`，
每轮含 `initiation` / `response` / `transport_keys` / `frames`）。

## 墙钟区段：不做逐字节比对

会话握手里嵌了**墙钟时间戳**（TAI64N），跨进程/跨次运行**不可能**一致。
会话向量用 `volatile_ranges` 声明「哪一段字节依赖墙钟」，
用 `volatile_layout` 说明该段的含义。

⇒ 比对时：`volatile_ranges` 声明的字节段**只查结构与长度**（位置对不对、
长度对不对），**不做逐字节比对**；该区段之外的**整份**都必须逐字节可复现。

## 密钥纪律

本目录里的密钥**全部是测试专用假值**（`0x11` / `0x22` / `0x33` / `0x44` /
`0x5a` 之类的模式字节，或由它们派生出的公开值）。

⛔ **不得**用于任何真实会话、任何真实密钥派生、任何生产配置。

## 单一真相

Rust 侧用 `include_str!` **指向本目录这三个文件**
（见 `crates/lengsuo-link-core/tests/vectors/` 与
`crates/lengsuo-link-core/tests/frame_vectors.rs`）。

⇒ 编译产物里的常量**就是**这些文件的内容，**结构上不可能**与文件漂移。

**改向量只能改本目录的文件**，不许在 Rust 源码里另存一份。
重新生成会话向量：
`cargo test -p lengsuo-link-core --test vectors_main -- --ignored --nocapture`，
把输出写进 `session-vectors.json`。

## 末尾换行是规范的一部分

三个 JSON 文件**必须以 `\n` 结尾**（与 Rust 侧规范渲染的输出保持一致）。

⇒ 编辑器 / 格式化工具**不要**自动去掉末尾换行，否则一致性用例会失败。

## ⛔ 不许改

这些字节是**跨端契约**。改动其中任何一个字节，都等于改协议：

- 必须同步**升 `version`**；
- 必须**通知移动端**；
- 必须重跑跨端对拍。

⛔ 也不许做「顺手格式化」（重排缩进、换成紧凑 JSON、补字段）——
向量按**逐字节**比对，格式一动即失效。
